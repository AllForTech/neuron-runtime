## Root cause
- `apps/web/stores/workflow/bootstrap/WorkflowSessionBootstrap.tsx:105-121` (pre-fix) — the draft subscription wrote on every dirty graph change and the autosave timer fired from an unsynced local draft with no `bootstrapStatus === 'loading'` guard; `apps/web/stores/workflow/commands/workflowCommands.ts:93,95` left the graph dirty after `updateGlobalVars` and completed bootstrap without cleaning it, so the load itself triggered a draft write (`apps/web/stores/workflow/adapters/workflowDraft.ts:31-38`).
- `apps/web/app/(editor)/Provider.tsx:13-19` (pre-fix) — the composition-edge `onError` sent every command error to `toast.error`, including `loadGraph`, `loadDeployment` and `getExecutionLogs`, which legacy logged only.
- `apps/web/stores/workflow/commands/workflowCommands.ts:129` (pre-fix) — `saveGraph` set `saveStatus` to `saved` but never scheduled the legacy `SAVED_STATUS_RESET_MS` (3000 ms) return to `idle`.
- `apps/web/stores/workflow/shim/legacyContext.ts:107-109,184-188` (pre-fix) — `selectLegacyLogsRecord` and `toLegacyLogs` were dead after the earlier `logs`-as-array fix.

## Fix
- `apps/web/stores/workflow/bootstrap/WorkflowSessionBootstrap.tsx:105-126` — skip `draftAdapter.put` while `sessionStore.getState().bootstrapStatus === 'loading'`, skip scheduling autosave while loading, and re-check the same flag inside the autosave callback. This restores the legacy in-flight load guard without changing any user-edit path.
- `apps/web/stores/workflow/commands/workflowCommands.ts:93-97` — call `deps.graph.getState().markClean()` after deployment load and before `completeBootstrap`, so a loaded graph is clean even though `transitions/graph.ts:146-151` marks `updateGlobalVars` dirty.
- `apps/web/app/(editor)/Provider.tsx:12-30` — added `LOG_ONLY_ERROR_CONTEXTS` for `loadGraph`, `loadDeployment` and `getExecutionLogs`; those contexts now call `console.error(message)` only. `saveGraph` and run/deploy/delete keep their unchanged legacy toast behavior.
- `apps/web/stores/workflow/commands/workflowCommands.ts:9,131-135` — after a successful save, schedule `setSaveStatus('idle')` after `SAVED_STATUS_RESET_MS` (3000 ms), matching the legacy timer.
- `apps/web/stores/workflow/shim/legacyContext.ts:106-115,178-185` — removed unused `selectLegacyLogsRecord` and `toLegacyLogs`; retained the used `toLegacyLogsRecord` write-boundary adapter.
- Pins unchanged: `zustand@5.0.12` and `happy-dom@21.0.4`; no new dependencies were added by this repair.
