## Behavior
- Live transform execution now runs in a separate V8 isolate with no host globals (`require`, `process` are `undefined`), a 1000 ms CPU timeout, and a bounded heap. No vm2 code runs on any execution path.
- Observable transform contract unchanged: successful transforms return `{ success: true, output: <value> }`; user exceptions still surface as `User Script Error: <message>`; missing results still surface as `Transform must return a value.`; timeouts still surface as `Execution Timeout: Transformation took too long.`
- The legacy API registry no longer references a transform executor; the canonical SDK executor remains the only implementation, wired via `packages/nodes/src/server/index.ts:1,16`.

## Risks and limitations
- `isolated-vm` is a native addon: CI/deploy hosts need a compatible prebuilt binary (via `prebuild-install`) or a node-gyp toolchain. Native build succeeded in this workspace; no process-isolation fallback was needed. `^5.0.4` was chosen deliberately — 6.x requires Node ≥22 and 7.x requires Node ≥24, while this repo declares Node `>=18`.
- `console.*` calls inside user scripts are intentional no-ops (no host I/O or host function references are passed into the isolate). User-visible transform results are unaffected; log output that vm2 previously redirected to the host console is not emitted.
- pnpm re-resolution refreshed 21 peer-suffix references from `postcss@8.5.9` to `postcss@8.5.33`, a version already present in the baseline lockfile. This is incidental lockfile churn from `pnpm add/remove`, not a new direct dependency; it was left as generated rather than hand-edited to avoid an inconsistent lockfile.
- Security sign-off is a separate task (T-107) and has not been recorded here.
