- Mode: read-only; no files modified by the research agent.

## Summary
Two genuine duplicate families exist:
- `framer-motion` and `motion` resolve to the same v12.38.0 engine; `motion` is a re-export with 7 live `motion/react` imports.
- `@xyflow/react` is a direct dependency with zero source usages; `reactflow` v11 is heavily used.

Root start scripts are broken:
- `start:api` points to nonexistent `apps/api/dist/apps/api/src/index.js`.
- `start` contains literal `node node`, the same bad path, and `&&`, so the web server cannot start while the API runs.

## Safe plan
- Rewrite 7 live `motion/react` imports to `framer-motion`, remove `motion`, keep `framer-motion` (19 imports).
- Remove unused `@xyflow/react`; keep `reactflow` v11 unless a deliberate v12 migration is approved.
- Repair `start:api` to invoke the backend start script with root env loading.
- Repair `start` using Turbo with a persistent `start` task, or a POSIX shell fallback.

## Validation
`pnpm install --frozen-lockfile`, check-types, lint, test, build, emitted-path assertions, and grep assertions for removed imports.

## Risks
Removing `framer-motion` instead of `motion` breaks pnpm-isolated imports. Env union must preserve root `VAULT_SECRET` and app-local `ENCRYPTION_KEY`/`PORT`. Native `isolated-vm` must be installed on the matching Node ABI.
