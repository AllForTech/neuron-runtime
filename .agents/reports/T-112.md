## Root cause
- Before the fix, `apps/api/src/controllers/deploy.workflow.controller.ts:201-207` and `apps/api/src/controllers/workflow.controllers.ts:333-339` constructed `ExecuteWorkflowUseCase` with default adapters inline, bypassing the existing `@/engine/execution` seam that controller tests mock; real collaborators were built from mocked DB exports, so execution threw and callers saw 500 instead of the frozen response shapes.
- `apps/api/src/application/deployed-execution.service.ts:5` imported `WorkflowExecutionResult` from the use-case, while the use-case only imported that type locally from the HTTP projector (old `execute-workflow.use-case.ts:5`), so the public type was never exported and backend typecheck failed with TS2459.
- The refactor left two same-named `RuntimeCollaborators` interfaces (application and adapters), an unreachable `executeWorkflowCommand` wrapper, and a comment describing T-112 as future work even though composition had already moved into the use-case.

## Fix
- `apps/api/src/application/execute-workflow.use-case.ts:6-15` — owns and exports `WorkflowExecutionResult`; `:28-32` is now the single exported `RuntimeCollaborators` definition; the dead `executeWorkflowCommand` helper was deleted (grep confirms zero callers).
- `apps/api/src/application/projectors/http-execution.projector.ts:1-2` — imports the result type from the use-case instead of declaring a duplicate; projector logic and wire literals unchanged.
- `apps/api/src/controllers/deploy.workflow.controller.ts:199-208` and `apps/api/src/controllers/workflow.controllers.ts:333-339` — route execution through the single `@/engine/execution` entry (`executeWorkflow(command, command.request)`), restoring the established mock seam without changing statuses, headers or bodies.
- `apps/api/src/adapters/defaultRuntimeCollaborators.ts:1-13` — imports the application-owned `RuntimeCollaborators` type, no longer declares/re-exports a competing interface, and the stale T-112 comment now states that the engine wrapper injects concrete collaborators into the application use-case.
- Deleted `apps/api/tests/debug-deploy.test.ts` (untracked debug artifact).
- Added `apps/api/tests/http-execution-projector.test.ts` — controller-boundary tests for terminal 201 headers/body, default 200 body, 500 error body, 202 accepted body, plus direct projector literal assertions.
