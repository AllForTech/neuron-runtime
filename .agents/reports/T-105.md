## Root cause
- `packages/db/src/services/VaultService.ts:26` — `resolve` computed `decryptedSecret` and cached it, but returned `secret.content` (raw ciphertext), so every caller that injected the resolved value received ciphertext.
- `apps/web/lib/utils.ts:234` — `const secret = process.env.VAULT_SECRET ?? '<64-hex AES key literal>'` supplied a hardcoded fallback, which also made the following `if (!secret)` missing-key guard unreachable dead code.
- `packages/shared/src/utils/logger.ts:20-71` — `format()` emitted `message`, `context` and `error` verbatim in all three output modes (production JSON, browser, Node), with no redaction of secret-named fields or secret-like value patterns.

## Fix
- `packages/db/src/services/VaultService.ts:26` — return `decryptedSecret` instead of `secret.content`. The cached path already stored the plaintext, so first and cached calls now both return plaintext; error and userId-scoped lookup behavior unchanged.
- `apps/web/lib/utils.ts:233` — `const secret = process.env.VAULT_SECRET;` removes the fallback literal so the existing `if (!secret) throw new Error('CRITICAL: VAULT_SECRET environment variable is missing.')` guard (`:234-235`) now runs. Web UI/public API unchanged; `getVaultKey` has no in-repo callers.
- `packages/shared/src/utils/logger.ts:6-50,72-84,100-129` — added `sanitizeString` / `sanitizeValue` / `sanitizeError` helpers that replace secret-named fields (`apiKey`, `password`, `authorization`, `client_secret`, …) and secret-like value patterns (`nrn_live_`, `nrn_test_`, `sk-`, `Bearer …`, GitHub/AWS key forms) with `[REDACTED]`, with cycle and Error-stack handling; applied them to message, context and error at every emission point. Output shape (`{timestamp, level, module, message, context, error}`, ANSI/DevTools formatting) and the logger's public methods are unchanged.
- `packages/db/src/services/VaultService.test.ts:2` — switched the test's cross-package relative import to the public `@neuron/shared/server` entry so `@neuron/db` typechecking no longer pulls another package's `src` outside its `rootDir` (TS6059); assertions untouched.

## Risks and limitations
- Redaction is pattern/field-name based: a credential placed in an arbitrarily named field with no recognizable prefix could still be logged. Tests cover the specified secret-like field names and prefixes.
- `logger.error` now logs a sanitized Error clone (message/name/stack plus redacted enumerable properties) rather than the original object; identity is not preserved, but all standard and custom fields remain visible.
- Removing the web fallback means `getVaultKey()` throws when `VAULT_SECRET` is unset; this is the required explicit-configuration contract, and the function currently has no callers.
- No live database test: plaintext return is proven with a mocked repository and real AES encrypt/decrypt.
- Vitest 5.1.1 on Node 20.19.5 cannot render failure details in the default reporter; JSON reporter was used for failure evidence. Passing runs are unaffected.
